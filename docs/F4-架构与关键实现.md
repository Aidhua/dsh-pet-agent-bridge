## 1. 总体架构

```
┌────────────────────────── DSH Host 进程（petlab profile）──────────────────────────┐
│                                                                                    │
│  dsh-pet 0.4.5（宠物本体）                     dsh-pet-task-ctl（伴随 bundle）     │
│  ┌──────────────────────────┐                 ┌──────────────────────────────────┐ │
│  │ chatWithPet()            │                 │ apply(ctx)                      │ │
│  │  └[PET-BRIDGE PATCH]     │  ctx.get        │  ├ petTaskCtl 服务（命令路由）    │ │
│  │   软查找 petTaskCtl ─────┼────────────────►│  ├ Agent Task Controller        │ │
│  │   /xxx → {handled,reply} │                 │  │   （请求轮询+状态机+超时）     │ │
│  │ createSessionNotify()    │                 │  ├ 长期记忆（pet-memory.json）   │ │
│  │  └ session 事件→workStatus│                 │  └ memory.register 聊天记忆提供者 │ │
│  └───────────┬──────────────┘                 └───────┬──────────┬─────────────┘ │
│              │                                        │          │               │
│              ▼                                        ▼          ▼               │
│  宠物气泡/聊天窗                              sessionController  ctx.on('session │
│  (thinking/working/…)                        .create/.prompt/     /event')        │
│                                              .cancel/.updateQueue                 │
└────────────────────────────────────────────────────────────────────────────────────┘
```

三个设计决策贯穿全部实现：

1. **伴随 bundle 而非改上游构建产物**：dsh-pet 的 lib 是 tsdown 产物，本地重建成本高；伴随 bundle 复用同一 cordis ctx、同一事件总线，加载即共存，卸载即回滚。对 dsh-pet 本体的唯一改动是一处 6 行的拦截补丁（web 面板与桌面助手共用 chatWithPet 入口）。
2. **零自绘 UI**：任务会话就是普通 DSH 会话，dsh-pet 原生 createSessionNotify 自动把 session 事件映射成宠物 workStatus（thinking/working/waiting/success）与完成气泡。桥接不画任何界面。
3. **双面记忆一份存储**：pet-memory.json 同时经官方 `petApi7340.memory.register`（唯一外部槽位）注入聊天 system，并作为 `[长期记忆]` 前缀注入每个 Agent 任务文本。一份存储、两个消费面。

## 2. 关键实现点

### 2.1 聊天命令路由（chatWithPet 拦截）
- petlab 副本 `chatWithPet` 头部插入补丁块：`ctx.get.call(ctx,"petTaskCtl",false)` **软查找**——桥接未加载时返回 false，原生流程原样继续，天然灰度开关。
- 路由（index.js `handleChatCommand`）：仅处理 `/` 开头且命令词在白名单（task/memory/记忆/称呼/owner/bridge）的输入，其余 `{handled:false}`。
- **中文无空格路由**：`/task 帮我创建…` 中第一个 token 就是整句，因此 status/list/cancel 之外的任何内容都作为任务全文提交（M1.1 修复项）。

### 2.2 任务提交（`startTask`）
- 会话策略：`opts.sessionId` 有值则复用（聊天通道来自 pet-memory 的 taskSessionId），否则 `controller.create({cwd})`；宠物工作区 `<home>/dsh-pet-task-ctl/workspaces/pet-<id>/`。
- 提交：`controller.prompt({requestId, sessionId, mode:"queue", content:[{type:"text",text}]}, abort.signal)`。
- prompt 被 Agent 接收时查 `agents.get(sid).status`，若他轮活跃则标 `queued`（排队真实可见）。

### 2.3 状态机（`handleSessionEvent`，只跟随真实事件）
```
accepted ──turn/start──► running ──approval/asked──► waiting_approval
   │                      │  ▲                            │approval/decided
   └─prompt parked─► queued│  └───────────────────────────┘
                          ├──turn/end(completed)──► completed
                          ├──turn/end(aborted)────► cancelled
                          └──turn/end(other)─────► failed
```
- 子代理隔离：`session.header.origin==='subagent' || delegationDepth>0` 的事件直接忽略，委派轮不污染任务状态。
- 结果文本：assistant/message 事件抽取 text parts 拼接。

### 2.4 取消语义（M1.1 核心）
1. `sessionController.cancel` 是**同步方法**（返回 receipt），按 Promise 调用会 TypeError 直接击穿 host——修复为同步调用+try/catch 兜底。
2. 顺序化决策：
   - 会话未建立 → `pendingCancel` 挂起，create 回调里直接终态；
   - 已入队未执行 → `updateQueue({action:{kind:'remove'},itemId})` 撤回（排队输入 cancel 不撤，必须显式 remove）；
   - prompt 尚未 resolve → `AbortController.abort()`；
   - 执行中 → `cancel({kind:'user'})` + 15s 宽限期等 `turn/end aborted`，无回执判 `failed(cancel-unconfirmed)`。
3. 同批次竞态：轮询两遍（submit 先、cancel 后）+ pendingCancel 双保险。

### 2.5 长期记忆
- 存储：`{pets:{<petId>:{ownerName, prefs[], taskSessionId}}}`，原子写（tmp+rename）。
- 注入限制：prefs≤50 条×200 字、称呼≤32 字。
- 聊天面：`petApi7340.memory.register({id:"pet-task-bridge", recall({petId,system})})` 返回 `{system: system+\n[长期记忆]…}`；load 顺序不保证，注册失败每 2s 重试直至 dsh-pet 就绪；卸载时 unregister。
- 任务面：任务文本前缀 `[长期记忆] 主人称呼：…。主人偏好：…` + 工作模式指示行。

### 2.6 M1.1 安全加固
- ID 白名单 `/^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/`（UUID 兼容）；sessionId 形状校验；cwd 必须绝对路径≤512 字符；text≤200k；请求文件≤1MB；字段数≤32。
- 重复请求 ID：内存去重 + 消费即删，重复回执带 `duplicate-request-id` 警告。
- 恶意文件名 sanitize（非白名单字符→`_`，前导点→`_`）。
