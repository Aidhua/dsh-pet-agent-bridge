## 1. 项目目标与结果

**目标**：让桌面宠物（dsh-pet）在保留原生陪伴聊天的基础上，获得真实的 Agent 工作能力——用户在宠物聊天窗里发 `/task <描述>`，宠物把任务交给 DSH Agent 真实执行（创建文件/整理文档等），并把长期记忆（称呼、偏好）同时用于聊天与任务，杜绝"聊天认识你、干活忘了你"。

**结果**：全部完成并通过真实端到端验证。5 个真实 E2E 场景（含模型真实调用、文件真实落盘、取消语义、取消后复用）全部通过，独立核验一致。

## 4. 关键能力一览

1. **聊天命令**：`/task`（提交/status/list/cancel）、`/memory`（list/add/del/clear）、`/称呼`、`/bridge` 帮助。
2. **真实 Agent 执行**：经原生 `sessionController.create/prompt/cancel`，非模拟；产出文件可独立核验。
3. **状态机**：accepted→queued/running→waiting_approval→completed/failed/cancelled，全部跟随真实 session 事件。
4. **审批透传**：DSH 原生审批（approval/asked）原样透传，不代答、不绕过。
5. **会话复用**：每宠物一个持久会话 ID，跨任务、跨 host 重启连续。
6. **双面长期记忆**：一份存储同时注入聊天 system（官方 petApi7340.memory.register 槽位）与每个 Agent 任务前缀。
7. **取消语义**：排队中→updateQueue.remove 撤回；执行中→session/cancel + turn/end aborted 确认；未入会话→pendingCancel 挂起。
8. **宠物状态联动**：任务即普通 DSH 会话，经 dsh-pet 原生 createSessionNotify 自动映射宠物 thinking/working/success 状态，桥接零额外 UI 代码。

## 5. 已知限制

- 文件请求入口（requests/ 轮询）为测试入口，保留但标注 TEST ENTRY；产品通道为聊天命令。
- 每宠物同时只允许一个在途任务（M1 范围设计，串行保证状态机清晰）。
- petlab 为开发验证环境；并入正式 desktop profile 前需按 F5 的迁移清单操作。
- 桥接命令目前仅支持简体中文命令词（/task /memory /称呼 /记忆 /owner /bridge）。
