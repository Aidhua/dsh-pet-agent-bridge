## 3. 现有 Bridge 是否可以扩展？

### 3.1 现状（源码证实，`integrations/dsh-pet-bridge/index.js`）

Bridge 是随 DSH Host 进程加载的 cordis 插件（`package.json` 的 `dsh.bundle.patch` → `cordis.patch.yml` insert），当前能力：

1. **DSH→Pet（已有）**：订阅 `agent/created`、`agent/status`、`session/event`（`apply(ctx)` L1038-1447），合批 80ms 写 `%APPDATA%\dsh-pet-bridge\dsh-{pid}.jsonl`（`writeRecord` L933）。
2. **Pet→DSH（已有雏形）**：控制队列轮询 `watchdog-request-*.json`（`startControlQueue` L230-264），支持 `interrupt`（`agent.cancel` L190）与 `replan`（`agent.cancel({keepInbox:true})` + `ctx.llm.stream` 诊断 + **`agent.steer()`** L209-212），响应写 `watchdog-response-*.json`。
3. **交互中继**：连 DSH WebSocket `/api/events.mux`（`muxConnect` L816-895），转发审批/问题帧（带 rpcId）供桌宠弹可点选气泡。

### 3.2 扩展性结论：**适合扩展，推荐作为主链路**

目标链路 Pet→Bridge→DSH Agent→Bridge→Pet 的两端都已存在：
- Pet→Bridge：文件请求协议已有（`dsh_control.py` 客户端 + Bridge 控制队列），只需**新增一种 operation**（如 `task`）。
- Bridge→Agent：Bridge 运行在 DSH Host 进程内，可注入 `ctx.agents`（AgentRegistry）——`ctx.agents.create(options)` 创建新 agent、`agent.followup(createUserMessage(...))` 提交任务（DSH 侧证据见 §4）。
- Agent→Pet：现有 `session/event` 订阅 + JSONL 转发原样复用，`tool/result` 事件已带 `resultText`。

无需引入新进程间通道，无需重构，符合"复用已有能力"原则。

### 3.3 必须处理的上游 API 漂移（本报告最重要的发现）

Bridge 及桌宠回写链路是针对 **DSH 0.1.1-rc.2** 写的（`integrations/dsh-pet-bridge/package.json` 依赖 `@deepseek-ai/dsh-*: ^0.1.1-rc.2`）。对照 DSH 当前源码（0.2.2-rc.1）：

| Bridge 引用 | 当前 DSH 源码 | 结论 |
|---|---|---|
| `inject: ["llm","agentDefaultModel","apiProxy"]`，`ctx.apiProxy.sessions.list`（index.js L18、L457） | 全库 grep `apiProxy` **零命中** | API 已不存在；元数据刷新会静默失败（代码本身已容错） |
| `ws://127.0.0.1:{port}/api/events.mux`（L824） | 真实端点为 **`/api/remote.mux`**（`packages/api/gateway/src/stream-protocol.ts:7`），帧协议也不同 | 交互审批中继对 0.2.x 静默失效，退化为"提示去 Web UI 点" |
| Pet `dsh_responder.py` POST `/api/respond`（L16） | 全库 grep `/api/respond` **零命中** | 审批/问题回写对 0.2.x 失效；新协议是 `POST /api/session/prompt`（关联 id 为 `requestId`） |

即：**事件订阅（cordis 事件面）在 0.2.x 仍然有效，但审批/问题交互回写与元数据链路已断**。第二阶段必须先对 0.2.x 重新核对 `session/event` 事件词表与交互通道。

## 4. DSH 原生 Agent API 真实可用性

### 4.1 官方提供的三条"外部程序驱动 Agent"路径（源码证实）

**路径 A：DSH 进程内插件（现有 Bridge 的形态，推荐扩展）**
- `ctx.agents`（AgentRegistry）契约：`docs/subsystems/core.md:683-850`，`async create(options): Promise<AgentHandle>`、`resume(options)`、`get(id)`；工厂由 `packages/core/agent-loop/src/index.ts:667` `AgentLoop.create` 实现。
- Agent 对象接口：`packages/core/agent/src/runtime-types.ts` L190-272 —— `followup(message)`（L251 排队下一轮）、`steer(message)`（L260 就近注入）、`cancel(cause, {keepInbox})`（L212）、`status: 'idle'|'running'`。
- 事件：`agent/status`（runtime-types.ts L309）、`session/event`（`packages/core/session/src/index.ts:76`）；事件类型全集 `packages/core/session/src/known-event-types.ts:22-86`（60 种，含 `turn/start`、`assistant/message`、`tool/call`、`tool/result`、`approval/asked`、`llm/retry` 等）。
- **插件主动提交新任务：可行**（`ctx.agents.create` + `agent.followup`）。

**路径 B：SDK stdio JSON-RPC（官方为外部进程准备的正式通道）**
- `packages/sdk/README.md`："drive a Harness runtime from another process"；`dsh --profile sdk`（`packages/bundle/sdk-app/cordis.patch.yml`）。
- 协议：`packages/sdk/protocol/README.md` —— `session/prompt`、`session/resume`、`session/wait`、通知 `session.event`/`session.status`、server→client `approval/request`（审批结果 `{outcome: 'allowed-once'|'rejected'|'cancelled'}`）。
- **官方 Python SDK 已存在**：`python/README.md` —— `deepseek-harness-sdk`（高层 turns API）+ `deepseek-harness-runtime-bin`，桌宠是 Python/PySide6，技术栈天然匹配。

**路径 C：HTTP/WS（可用但非公开外部 API）**
- `POST /api/session/create`（`packages/api/session-controller/src/index.ts:306`，args `{workspaceId?|cwd?, sessionId?, agentPreset?}`）、`POST /api/session/prompt`（L467，args `{requestId, sessionId, mode:'queue'|'steer', content}`，响应 `{accepted:true}`，requestId 幂等去重 `commands.ts:390-413`）。
- `prompt` 实现落点：`mode==='steer'` → `agent.steer`，否则 `agent.followup`（`commands.ts:373-374`）——与路径 A 汇合。
- 冷恢复：`resolveAgent` 会自动恢复已持久化的历史 session（`commands.ts:542-546`，`docs/api-gateway.md:132`）；但 `cancel` 不做冷恢复（`commands.ts:526-534`）。
- 限制：`session.cancel` 语义是 `agent.cancel({kind:'user'},{keepInbox:true})`（只中止当前轮）；HTTP 需过 Connection 的 cookie/Host 信任边界（`docs/api-gateway.md:128`），文档未将其列为公开外部 API。

### 4.2 针对任务书各检查项的逐条回答

| 检查项 | 结论 | 证据 |
|---|---|---|
| Agent 创建/恢复 | ✅ `ctx.agents.create/resume`（进程内）；`session/create` + 冷恢复（HTTP）；`session/resume`（SDK） | core.md:683+；session-controller/src/index.ts:306 |
| 提交自然语言任务 | ✅ `agent.followup/steer`；HTTP `session/prompt`；SDK `session/prompt` | agent.ts:179-185；commands.ts:373-374 |
| 状态与事件订阅 | ✅ `ctx.on('agent/status'/'session/event')`（进程内）；SDK 通知 `session.event/session.status`；HTTP `session.observeEvent/follow` stream | runtime-types.ts L309；sdk/protocol/README.md |
| 流式消息 | ✅ `agent/assistant-stream` 事件（帧 start/chunk/end，runtime-types.ts L399、L155-188）；SDK/HTTP 流式经 `/api/remote.mux` | 已证实 |
| 工具权限审批 | ✅ `packages/interaction/user-approval`：`ApprovalOutcome = 'allowed-once'|'rejected'|'cancelled'|'unavailable'`（types.ts:32），fail-closed；事件 `approval/asked {id, toolName, callId?}` / `approval/decided {id, outcome}`；外部应答走 SDK `approval/request` | approval.md:36-90 |
| 工作区↔会话 | ✅ `SessionCreateRequest {workspaceId?|cwd?}` 互斥（session-controller/src/types.ts:268-277）；创建后 `workspace.attachSession`（commands.ts:147-157） | 已证实 |

| **插件能否主动提交任务** | ✅ **能**。`ctx.agents.create` + `agent.followup` 是直接证据；不存在"只能监听不能提交"的限制 | core.md:760-767 |

### 4.3 概念纠偏（任务书特别要求）

- Bridge 里的"控制"（interrupt/replan via `agent.cancel/steer`）只对**已存在的 live agent** 生效；当前 Bridge **没有**创建新 session/新任务的能力——这正是第二阶段要补的 `task` operation。
- `apiProxy`、`/api/respond`、`/api/events.mux` 是旧版（0.1.x 时代）概念，当前 0.2.x 已不存在，研究任何"以官方 API 为准"的方案时不得引用桌宠仓库内的旧接口名。

## 5. 推荐系统架构与通信方式

### 5.1 IPC 四方案比较

| 方案 | 开发成本 | 实时性 | 稳定性 | Windows 兼容 | 安全 | 结论 |
|---|---|---|---|---|---|---|
| **文件事件桥（现有 JSONL + request/response 文件）** | 最低（两端代码已在生产使用） | 轮询 1.2-1.5s，可调到 200ms 级 | 已被 1322 测试+生产验证；`dsh-{pid}.jsonl` 分实例写、原子写、轮转齐全 | ✅ `%APPDATA%` 路径，无特殊 API | 本机用户目录，无网络面 | **首选** |
| 本地 HTTP `/api/session/*` | 中（需处理 cookie/Host 信任边界） | 好 | 受官方支持但非公开外部 API，随版本漂移风险同 Bridge | ✅ | 本机回环但有信任机制 | 备选 |
| WebSocket `/api/remote.mux` | 中高（面向浏览器，cookie 鉴权） | 最好 | 同上 | ✅ | 需 cookie | 不推荐 |
| Named Pipe | 高（DSH 不暴露，需在插件里自建服务端） | 好 | 需自研协议与重连 | 需处理管道命名/ACL | 可控 | 不推荐 |
| SDK stdio JSON-RPC | 中（官方 Python SDK 现成，但要求 Pet 拥有 DSH 子进程） | 好 | 官方契约，最抗漂移 | ✅ | stdio 无网络面 | **Plan B** |

SDK profile 与 web profile 不能同进程共存（`docs/user/guide/python-sdk.md`），走 SDK 意味着桌宠自持一个 DSH 运行时实例，与用户日常用的 web 实例形成两个进程——拓扑复杂化，故列为 Plan B。

### 5.2 推荐架构（扩展现有 Bridge，最小改动）

```
[Pet 聊天窗口] --(识别为 Agent 任务)--> [Pet: 新 task_client（复用 dsh_control.py 协议）]
      写 %APPDATA%\dsh-pet-bridge\pet-request-<uuid>.json
      轮询 pet-response-<uuid>.json
            │
            ▼
[Bridge 扩展：新增 task 控制器]
  1) ctx.agents.create({cwd|workspaceId, agentPreset?}) 或 resume 历史 session
  2) agent.followup(createUserMessage({text: 任务, source:{kind:'plugin', plugin:'dsh-pet-bridge'}}))
  3) 订阅该 agent 的 session/event，直到 turn/end
            │
            ▼
[现有 JSONL 事件流（不变）] --> [Pet: AgentLinkManager 气泡 + DshStateTracker 状态机（本次接线上线）]
      tool/result.resultText / turn/end  --> [Pet 显示执行结果与文件路径]
```

要点：
- 请求文件与现有 `watchdog-request-*` 同目录同协议风格，但用独立前缀（`pet-request-*`），不与 watchdog 混队。
- Bridge 端在 `task` 完成时写一条结构化 `pet/task-result` 记录（含 sessionId、结果文本、产物路径），Pet 据此闭环。
- 审批/问题交互：0.2.x 下旧 mux 中继已失效；第一阶段 MVP 先依赖 DSH 自己的 Web UI 完成审批（Pet 仅展示 `approval/asked` 状态），交互回写留待第二阶段按 SDK 协议或 `session/prompt` 重做。

## 7. 兼容性与权限风险

1. **API 漂移（最高风险）**：桌宠仓库基于 DSH 0.1.1-rc.2，官方已演进到 0.2.2-rc.1；`apiProxy`/`/api/respond`/`/api/events.mux` 已消失【源码证实】。第二阶段开工前必须以 0.2.x 源码重核 `session/event` 词表与 `ctx.agents.create` 的 `CreateAgentOptions` 具体字段（`docs/subsystems/core.md` 为生成文档，最终以类型定义为准）【待运行验证】。
2. **`ctx.agents.create` 参数细节**：`agentPreset`、workspace/cwd 传参的确切 schema 在生成文档与类型之间可能有出入，需读 `packages/core/agent-loop` 类型实现后确认【推断+待验证】。
3. **审批交互回写缺失**：0.2.x 下 Pet 无法再直接代答审批（旧 `/api/respond` 已失效）；MVP 期间审批在 DSH Web UI 完成，Pet 只提示。
4. **模型调用计费**：DSH Agent 执行任务必然触发模型请求（用户自己的 provider/key）。验证 hello.txt 场景会产生真实 token 消耗，需用户在 DSH 侧自行配置模型后再测。
5. **多实例/端口**：桌宠按 `{DSH_PORT, 38080, 3080}` 探测；Bridge 文件目录跨平台定义一致（index.js L54-62 与 dsh_control.py L15-21 已对齐），风险低。
6. **许可证与署名**：两仓 MIT；改造分发需保留 Merzlin 与 DeepSeek 版权声明及 `THIRD_PARTY_NOTICES.md`。
7. **Windows 特有**：Bridge 写盘轮转已处理 `rename` 不能覆盖问题（index.js L920-925）；桌宠会话写入有 PermissionError 退避（session_store.py L183-195）。均为已解决问题。

## 8. 最小 MVP 开发计划

**验证场景**：用户在 Pet 聊天框输入"帮我在测试工作区创建 hello.txt，内容为：你好，我是你的 AI 小鱼。"

| 阶段 | 内容 | 预估规模 |
|---|---|---|
| M0 上游核对 | 对照 0.2.2-rc.1 确认 `ctx.agents.create`/`followup` 签名、`session/event` 词表、`CreateAgentOptions` 字段；升级 Bridge 依赖版本声明 | 只读，0.5 天 |
| M1 Bridge `task` operation | 控制队列新增 task 分支：`pet-request-*.json` → `ctx.agents.create({cwd: 测试工作区})` → `agent.followup(用户文本)` → 监听至 `turn/end` → 写 `pet-response-*.json` + `pet/task-result` JSONL 记录 | Bridge 端 ~150 行 |
| M2 Pet 任务入口 | `dsh_control.request()` 白名单加 `task`；聊天窗加"Agent 任务"开关（第一阶段用显式开关，不做意图识别）；发送后展示"任务进行中"状态 | ~100 行 |
| M3 状态接线 | `app.py` 连接 `DshStateTracker.state_changed` → PetWindow；`tool/call`→working、`turn/end`+`pet/task-result`→结果气泡（含文件路径） | ~60 行 |
| M4 端到端验收 | 真实 DSH + 真实模型跑通 §9 场景；文件系统核验 | 测试 |

明确禁止项（按任务书）：Pet 不直接写文件、不模拟 Agent 回复、不伪造调用成功。

## 9. 每阶段验收标准

| 阶段 | 验收标准 |
|---|---|
| M0 | 出一份 0.2.x API 核对清单，每项附类型定义文件路径与符号名；Bridge 依赖版本更新后 `verify_import.mjs` 逻辑可静态过检 |
| M1 | 手工放置 `pet-request-*.json`（固定 sessionId 为空=新建），Bridge 日志/JSONL 出现 `agent/created`→`turn/start`→`tool/call`→`turn/end`→`pet/task-result` 全链路记录 |
| M2 | Pet 聊天框发送任务后，`%APPDATA%\dsh-pet-bridge\` 出现 request 文件并在超时内收到 response；超时/拒绝有明确 UI 提示 |
| M3 | Pet 动画进入 working 态；结束后气泡展示结果文本与文件路径；状态与 JSONL 事件可对账 |
| M4 | **完整场景闭环**：① Pet 收到消息 ② Bridge 交给 DSH 原生 Agent ③ DSH 执行创建 ④ Pet 显示执行状态 ⑤ 返回结果与路径 ⑥ **独立校验文件存在且内容一致**（校验由人工或测试脚本做，不由 Pet 伪造） |

## 10. 推荐的下一步实施命令（第二阶段开工时用）

```bash
# 0. 确认本地 DSH 版本（第二阶段以实际安装版本为准，源码核对结论需对齐）
dsh --version

# 1. 基于 0.2.x 升级 Bridge 依赖声明后，本地装桥（Pet 已有现成入口）
#    或手动：cd integrations/dsh-pet-bridge && dsh plugin add .（以 0.2.x CLI 实际命令为准）

# 2. 启动 DSH（web profile，桌宠菜单"启动 DeepSeek Harness"亦可）
dsh web --port 38080

# 3. MVP 手工验证 Bridge task 链路（不经 Pet UI，先隔离验证 M1）
#    写入请求文件后观察 %APPDATA%\dsh-pet-bridge\ 下 dsh-*.jsonl 事件流
echo '{"id":"t1","ts":0,"operation":"task","sessionId":"","text":"帮我在测试工作区创建 hello.txt，内容为：你好，我是你的 AI 小鱼。"}' > "$APPDATA/dsh-pet-bridge/pet-request-t1.json"

# 4. 独立核验产物
cat "<测试工作区>/hello.txt"
```
