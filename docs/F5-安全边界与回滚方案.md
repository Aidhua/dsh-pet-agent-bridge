# F5 安全边界与回滚方案

- 日期：2026-11-08

---

## 1. 隔离边界（本次全程遵守）

### 1.1 环境隔离
- **petlab 隔离环境**：所有开发、测试、E2E 都在 `DSH_HOME=research/env/dsh-home` 下进行。DSH_HOME 优先级（显式配置 > $DSH_HOME > ~/.dsh）保证 petlab 与正式环境物理隔离。
- **正式环境零修改**：`~/.dsh` 全程未动。阶段 F 复验：`~/.dsh/profiles/desktop/node_modules/dsh-pet/lib/index.js` SHA256 = 基线 `19c5587b…ef523`。
- **上游仓库零修改**：`research/repos/` 下两仓库只读审查，未安装依赖、未执行其代码。

### 1.2 凭据安全
- `.credentials.yaml` 仅为 E2E 只读复制进 petlab，原件未动；文档与代码中不落任何凭据明文（token 属临时会话凭据，host 重启即失效）。
- HTTP 侧沿用 DSH 原生信任栅栏：token→cookie（302 Set-Cookie），后续 API 凭 Cookie；不绕过、不放宽。

### 1.3 硬件与系统红线（用户最高底线）
- **绝对未接触**：Windows Update、BIOS、固件、驱动。全程任何阶段均未出现需要操作上述内容的步骤；若未来任务涉及，一律立即停止并请示。

### 1.4 代码层安全
- 请求校验：ID/sessionId 白名单正则、cwd 绝对路径校验、长度上限（text 200k / 文件 1MB / 字段 32）。
- 文件写入：全部在 `<DSH_HOME>/dsh-pet-task-ctl/` 内；文件名 sanitize 防路径穿越；原子写（tmp+rename）防半写。
- 审批不代答：DSH 原生 approval/asked 原样透传给用户，桥接无任何自动批准逻辑。
- 插件异常隔离：所有 handler try/catch 兜底，单个请求异常不击穿 host。

## 2. 回滚方案（从轻到重）

### L1 — 卸载桥接 bundle（推荐首选，可逆）
```jsonc
// research/env/dsh-home/profiles/petlab/package.json
// bundles 与 dependencies 中删除 "dsh-pet-task-ctl" 两条目
// 同步删除 node_modules/dsh-pet-task-ctl/
```
重启 host 后：聊天命令失效，宠物原生功能完全不受影响（拦截补丁软查找返回 false，自动走原生流程）。pet-memory.json、workspaces 产物保留。

### L2 — 还原 dsh-pet 拦截补丁
```bash
cp profiles/petlab/node_modules/dsh-pet/lib/index.js.orig-backup \
   profiles/petlab/node_modules/dsh-pet/lib/index.js
```
或从基线 `research/dev/dsh-pet-0.4.5-baseline/lib/index.js`（SHA256 `19c5587b…ef523`）复制。校验：`sha256sum` 比对。

### L3 — 整个 petlab 环境废弃
`research/env/dsh-home/` 整目录删除即可（自包含）。不影响正式环境任何数据。

### L4 — （未来若已并入正式 desktop profile）
1. 从 desktop profile 的 package.json 移除 bundle 条目，删 node_modules 副本；
2. 用基线副本还原 `~/.dsh/profiles/desktop/node_modules/dsh-pet/lib/index.js`（先备份当时的版本）；
3. 删除 `~/.dsh/dsh-pet-task-ctl/`（产物目录；**删除前先备份 pet-memory.json 与 workspaces 中的用户文件**——属用户个人数据）。

## 3. 正式环境迁移清单（若未来启用）

1. **备份**：完整备份 `~/.dsh/profiles/desktop/node_modules/dsh-pet/lib/index.js` 与 `~/.dsh/profiles/desktop/package.json`。
2. **部署 bundle**：拷贝 `research/dev/dsh-pet-task-ctl/` 至 desktop node_modules；package.json 增加 bundles/dependencies 条目（UTF-8 **无 BOM**——见 F6 教训 1）。
3. **打补丁**：对 desktop dsh-pet lib/index.js 应用同一拦截块（先留 `.orig-backup`）。
4. **验证**：`/bridge` 命令冒烟 → 提交一个只读型小任务 → 核验产出 → 观察宠物状态映射。
5. **观察期**：保留 L1/L2 回滚能力 48h；pet-memory.json 每日备份。
6. **红线复述**：迁移过程中同样绝不触碰 Windows Update、BIOS、固件、驱动；仅限 `~/.dsh` 目录内文件操作。

## 4. 数据归属与隐私

- pet-memory.json（称呼/偏好）与 workspaces 产物均为**用户个人数据**，任何清理/回滚操作涉及它们时须先备份并征得用户确认；绝不静默删除。
- 任务回执（results/）含任务文本与结果摘要，属开发测试数据，回滚 L3 时可随环境一并清理。
